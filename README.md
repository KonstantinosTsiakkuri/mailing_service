# Сервис рассылок

Учебный веб-сервис управления email-рассылками на Django (курсовая работа SkyPro).

Возможности:
- регистрация с подтверждением email, вход по email, выход, восстановление пароля;
- свои клиенты (получатели), сообщения (тема и текст письма) и рассылки у каждого пользователя;
- отправка рассылки кнопкой на сайте или командой из терминала, учёт попыток отправки;
- главная страница с общими показателями и страница личной статистики;
- роли: обычный пользователь и менеджер (просмотр всех данных, блокировка пользователей, отключение рассылок);
- кэширование (Redis или память процесса).

## Технологии
Python 3.13, Django 6.1, PostgreSQL, Poetry, Bootstrap 5 (CDN), опционально Redis.

## Установка

1. Установите зависимости:
   ```
   poetry install
   ```
2. Создайте базу данных PostgreSQL (например, `mailing_db`) и пользователя с доступом к ней.
3. Создайте файл `.env` в корне проекта по образцу `env_example` и впишите свои значения:

   | Переменная | Обязательна | Назначение |
   |---|---|---|
   | `SECRET_KEY` | да | секретный ключ Django |
   | `DEBUG` | да | `True` для разработки |
   | `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` | да | подключение к PostgreSQL |
   | `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USE_SSL`, `EMAIL_USE_TLS`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL` | нет | реальная отправка почты (см. ниже) |
   | `REDIS_URL` | нет | кэш в Redis (см. ниже) |

   Строки из `env_example` нужно скопировать и заменить текст «ВСТАВЬТЕ СЮДА …» своими значениями. Необязательные переменные можно не указывать.
4. Примените миграции:
   ```
   poetry run python manage.py migrate
   ```
   Миграции сами создают группу «Менеджеры» с нужными правами.
5. Создайте суперпользователя (вход идёт по email):
   ```
   poetry run python manage.py createsuperuser
   ```
6. Запустите сервер:
   ```
   poetry run python manage.py runserver
   ```
   Сайт: http://127.0.0.1:8000/ , админка: http://127.0.0.1:8000/admin/

## Как пользоваться

1. Зарегистрируйтесь (`/users/register/`). Пока почта не настроена, письмо со ссылкой подтверждения печатается в окне терминала, где запущен сервер — скопируйте ссылку в браузер.
2. Добавьте клиентов, сообщение и создайте рассылку (меню «Клиенты», «Сообщения», «Рассылки»). Даты начала и окончания задают период, в который рассылку можно отправить.
3. Отправка рассылки:
   - **с сайта** — откройте рассылку и нажмите «Отправить»;
   - **из терминала** — `poetry run python manage.py send_mailing <id рассылки>`.

   Отправка возможна только в период между началом и окончанием и только если рассылка не отключена менеджером. Результат каждой отправки (по получателю) виден в таблице «Попытки отправки» и в разделе «Статистика».

## Менеджеры
Менеджер — это пользователь из группы «Менеджеры». Назначение: `/admin/` → «Пользователи» → выбрать пользователя → в поле «Группы» добавить «Менеджеры» → «Сохранить».
Менеджер видит всех клиентов и рассылки (но не может менять и удалять чужие), видит список пользователей и может их блокировать/разблокировать, отключать и включать рассылки.

## Настройка почты
Без настроек письма выводятся в терминал. Для реальной отправки добавьте в `.env`, например, для Яндекс Почты:
```
EMAIL_HOST="smtp.yandex.ru"
EMAIL_PORT="465"
EMAIL_USE_SSL="True"
EMAIL_USE_TLS="False"
EMAIL_HOST_USER="ваш_логин@yandex.ru"
EMAIL_HOST_PASSWORD="пароль приложения"
DEFAULT_FROM_EMAIL="ваш_логин@yandex.ru"
```
Пароль приложения создаётся в настройках безопасности аккаунта (обычный пароль от почты не подойдёт). Для Gmail: `smtp.gmail.com`, порт 465, SSL.

## Настройка Redis (необязательно)
Без `REDIS_URL` кэш хранится в памяти процесса — этого достаточно для разработки. Для Redis:
1. Установите и запустите Redis (Windows: Memurai, WSL — `sudo apt install redis-server`, или Docker — `docker run -d -p 6379:6379 redis`).
2. Добавьте в `.env`: `REDIS_URL="redis://127.0.0.1:6379/1"`.
3. Перезапустите сервер.

## Структура проекта
- `config/` — настройки и главный файл адресов.
- `mailing/` — клиенты, сообщения, рассылки, попытки; отправка (`services.py`), команда `send_mailing`, кэш (`signals.py`).
- `users/` — пользователь с входом по email, регистрация, восстановление пароля, список и блокировка пользователей.
- `templates/base.html` — общий шаблон страниц.

Подробные разборы кода по этапам разработки лежат в папке `Claude_code/` (она не попадает в git).
